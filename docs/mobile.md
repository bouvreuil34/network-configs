# Мобильный профиль Shadowrocket

Эта спецификация задаёт намеренное поведение `shadowrocket/mobile.conf`. Будущие изменения конфига следует проверять относительно неё. Приоритеты hobby-проекта — простота, прозрачность, предсказуемость и минимум обслуживания.

Профиль Mobile использует **DIRECT по умолчанию**. VPN включается только для явно перечисленных ниже сервисов и списков. Российские домены и IP идут напрямую, если не совпали с явным VPN-правилом. Общей маршрутизации по России нет; `Российские серверы LTE` автоматически выбирает российский LTE-сервер для Горпарковок и ATOMIC PR. Последнее правило — `FINAL,DIRECT`.

## DNS, IP и локальная сеть

DIRECT использует системный DNS текущей сети: в мобильной сети — DNS оператора, дома по Wi-Fi — через Netcraze к DNS, полученным от провайдера МТС. `dns-server = system`; `dns-direct-system` включён, `dns-fallback-system` и `dns-direct-fallback-proxy` выключены. Отдельный fallback DNS в Shadowrocket не используется. Публичный DoH намеренно не используется для обычного DIRECT-трафика из-за возможных проблем с географическим выбором российских CDN.

Для доменных VPN-правил с политиками `Обход блокировок`, `Российские серверы LTE` и `Турецкие серверы LTE` используется стандартное поведение DNS в Shadowrocket. Конкретный DNS resolver на стороне прокси этим конфигом не задаётся.

Имена VPN-узлов, включая узлы из подписки, разрешаются отдельно через Cloudflare и Google DoH с `#no-h3` в `proxy-dns-server`. DNS обычного DIRECT-трафика остаётся системным. Если при режиме белых списков VPN перестанет подключаться, первым аварийным вариантом заменить настройку на проверенный Яндекс DNS:

```ini
proxy-dns-server = 77.88.8.8
```

IPv6 намеренно отключён: `ipv6 = false`, `prefer-ipv6 = false`. Ответы DNS с частными IP разрешены (`private-ip-answer = true`). Локальная сеть не блокируется: localhost, домены `.arpa`, `.lan`, `.local`, частные, link-local и multicast адреса IPv4/IPv6 обрабатываются напрямую. DIRECT-правила IPv6 сохраняют это намерение при отключённом IPv6.

Сохраняются `bypass-system = true`, `block-quic = all-proxy` и `udp-policy-not-supported-behaviour = REJECT`. Адрес обновления профиля: `https://raw.githubusercontent.com/bouvreuil34/network-configs/main/shadowrocket/mobile.conf`.

## Выбор VPN

Группа `Обход блокировок` по умолчанию использует `Зарубежные серверы LTE` (`select=0`). Четыре группы ниже берут узлы из подписки **Платный VPN**. Три автоматические группы используют `fallback` с проверкой доступности по `https://cp.cloudflare.com/generate_204` каждые 120 секунд и тайм-аутом 4 секунды.

- **Зарубежные серверы LTE** выбирает узлы с отметкой `LTE`. Для исключения `LTE №61` используется граница слова после номера. Узлы с номером 610 проходят обычный отбор. Также исключаются имена с `Авто`, `Москва`, `МСК`, `Санкт-Петербург`, `СПБ`, `Екатеринбург`, `Хабаровск`, `Россия` или `РФ` в любой позиции. Отдельное исключение для `LTE - Безлимит #1 | Torrent` действует без учёта регистра.
- **Российские серверы LTE** обслуживает Горпарковки и ATOMIC PR. В имени должны встречаться `LTE` и одно из обозначений `Екатеринбург`, `Москва`, `МСК`, `Россия`, `РФ`, `Санкт-Петербург`, `СПБ` или `Хабаровск` в любом порядке. Отметка `Авто` в любой части имени исключает узел.
- **Турецкие серверы LTE** обслуживает OpenAI. После `LTE` должно встретиться слово `Турция`. Записи `LTE Авто` исключены.
- **Ручной выбор LTE** показывает все узлы с `LTE` в названии. Чтобы использовать выбранный сервер, укажите эту группу в `Обход блокировок`. OpenAI, Горпарковки и ATOMIC PR всегда обращаются напрямую к своим страновым группам.

Фильтры используют имена из подписки. При переименовании узлов их принадлежность к группе может измениться.

## Маршрутизация

Правила применяются сверху вниз до первого совпадения. Таблица задаёт их порядок.

Приоритет исключений и положение IP-правил с `no-resolve` сохраняются. Страновые правила OpenAI стоят перед общими сервисными списками; `FINAL` остаётся последним.

Google, Meta, Telegram и весь YouTube всегда идут через VPN с политикой `Обход блокировок`.

| Трафик | Маршрут |
| --- | --- |
| Локальные и служебные домены и адреса | `DIRECT` |
| OpenAI: `cdn.openaimerge.com`, имена с `chatgpt-async-webps-prod-`, затем `geosite-openai.list` | `Турецкие серверы LTE` |
| `captive.apple.com`, `push.apple.com` и поддомены push | `DIRECT` |
| Остальной Apple: `Apple_Domain.list` и `Apple.list` | `Обход блокировок` |
| AWS: `amazonaws.com` и поддомены | `Обход блокировок` |
| Google | `Обход блокировок` |
| Meta по доменам | `Обход блокировок` |
| Prefect / FastMCP / Horizon: `fastmcp.app`, `gofastmcp.com`, `prefect.cloud`, `prefect.io`, `workos.com` и их поддомены | `Обход блокировок` |
| Telegram по доменам | `Обход блокировок` |
| YouTube | `Обход блокировок` |
| ATOMIC PR (`atomic-pr.ru` и поддомены) | `Российские серверы LTE` |
| Горпарковки: `volgaparking.ru` и поддомены | `Российские серверы LTE` |
| Mobile allowlist: `geosite-ru-mobile-whitelist.list` | `DIRECT` |
| `inside-clashx.lst`: ресурсы, проблемные или ограниченные из России | `Обход блокировок` |
| `no-russia-hosts`: ресурсы, ограничивающие доступ с российских IP | `Обход блокировок` |
| Meta по IP | `Обход блокировок` |
| Telegram по IP | `Обход блокировок` |
| Всё остальное, включая российские домены/IP без совпадения выше (`FINAL`) | `DIRECT` |

`cdn.openaimerge.com` нужен OpenAI, но отсутствует в используемом [geosite-openai.list](https://raw.githubusercontent.com/Master-Yoba/shadowrocket-rules/release/rules-geosite/geosite-openai.list), поэтому перед списком сохранено отдельное доменное правило.

`DOMAIN-KEYWORD,chatgpt-async-webps-prod-,Турецкие серверы LTE` направляет динамические соединения ChatGPT в `webpubsub.azure.com` через группу `Турецкие серверы LTE`. В upstream этот шаблон представлен как `URL-REGEX`; отдельное доменное правило сохраняет нужный маршрут для HTTPS/WSS без MITM, как в Wi-Fi-профилях.

Горпарковки (`volgaparking.ru` и поддомены) — точечное исключение: `DIRECT` не подходит в режиме белых списков оператора, поэтому сервис использует российский LTE-VPN через `Российские серверы LTE`. Правило стоит перед Mobile allowlist и действует независимо от выбора в `Обход блокировок`. Общей маршрутизации российских доменов через `Российские серверы LTE` нет.

[Mobile allowlist](https://raw.githubusercontent.com/Master-Yoba/shadowrocket-rules/release/rules-geosite/geosite-ru-mobile-whitelist.list) применяется после сервисных VPN-правил и перед списками ограниченных ресурсов. Оба источника ограниченных ресурсов сохраняются: [inside-clashx](https://raw.githubusercontent.com/itdoginfo/allow-domains/main/Russia/inside-clashx.lst) и [no-russia-hosts](../shadowrocket/no-russia.list). Они описывают разные причины ограничения доступа.

`no-russia-hosts` подключается как `RULE-SET` из записей `DOMAIN-SUFFIX` с политикой `Обход блокировок`, охватывая родительский домен и поддомены. [Обновление профиля и списка](../README.md#обновление-shadowrocket-и-списков).
